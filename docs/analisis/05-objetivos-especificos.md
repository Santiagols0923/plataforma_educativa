Objetivos Específicos

Fase de Análisis que, para que y porque

Identificar las dificultades pedagógicas, académicas y socioeconómicas que afectan el aprendizaje de la división en estudiantes de quinto grado, para comprender las causas del bajo desempeño matemático y proponer estrategias adecuadas de mejora. 
Analizar los vacíos en operaciones básicas como suma, resta y multiplicación, para determinar cómo influyen en la comprensión de la división y fortalecer las bases matemáticas de los estudiantes. 
Evaluar la disponibilidad y uso de recursos didácticos y tecnológicos en instituciones públicas de Medellín, para reconocer las limitaciones y oportunidades en la implementación de herramientas educativas digitales.

Investigar metodologías pedagógicas activas y estrategias de gamificación aplicadas a las matemáticas, para diseñar una experiencia de aprendizaje más dinámica, interactiva y significativa. 
Analizar plataformas, aplicaciones y recursos educativos existentes relacionados con la enseñanza de la división, para identificar fortalezas, debilidades y oportunidades de mejora que puedan incorporarse en la propuesta del sistema.

Definir los requisitos funcionales y no funcionales de la plataforma web educativa, para garantizar que el sistema responda a las necesidades pedagógicas, técnicas y de usabilidad de los usuarios. Fase de Diseño Diseñar la estructura de la plataforma web, incluyendo módulos de inicio, registro, contenidos y prácticas interactivas. Diseñar actividades, juegos, videos y recursos pedagógicos enfocados en operaciones básicas y la división. Planificar la integración de herramientas de IA (como Copilot) para ofrecer ejercicios personalizados y acompañamiento interactivo.

Fase de Construcción Desarrollar la plataforma web educativa con los módulos definidos (registro, contenidos, juegos, videos, IA). Implementar el módulo de prácticas para refuerzo de operaciones básicas (suma, resta, multiplicación) previo al aprendizaje de la división. Integrar recursos interactivos como juegos, imágenes y videos que faciliten la comprensión de la división.

Fase de Pruebas Realizar pruebas de funcionalidad, usabilidad y accesibilidad para asegurar que la plataforma sea comprensible, atractiva y adecuada para estudiantes de estratos 1–3. Validar la efectividad pedagógica de los módulos mediante pruebas con usuarios (estudiantes y docentes). Ajustar y optimizar la plataforma según los resultados obtenidos en las pruebas.

Requisitos no funcionales
RNF-13.1 Disponibilidad El sistema debe garantizar una disponibilidad mínima del 99.9%. RNF-13.2 Seguridad El sistema debe proteger los datos mediante cifrado en tránsito (TLS 1.2 o superior) y almacenamiento seguro. RNF-13.3 Rendimiento El sistema debe responder en menos de 2 segundos en operaciones críticas. RNF-13.4 Escalabilidad El sistema debe soportar el crecimiento de usuarios sin afectar el rendimiento. RNF-13.5 Usabilidad El sistema debe ser intuitivo, amigable y comprensible para estudiantes de primaria entre 10 y 11 años. RNF-13.6 Accesibilidad El sistema debe ser accesible, con diseño adaptado a niños y fácil interacción. RNF-13.7 Compatibilidad El sistema debe funcionar en dispositivos de bajo costo y navegadores comunes. RNF-13.8 Rendimiento en ejercicios El sistema debe cargar ejercicios y mostrar retroalimentación en menos de 2 segundos. RNF-13.9 Integración externa El sistema debe permitir integración con plataformas de video y servicios de apoyo educativo. RNF-13.10 Disponibilidad offline parcial El sistema debe permitir acceso limitado a contenidos previamente cargados sin conexión a internet. RNF-13.11 Mantenibilidad El sistema debe permitir actualizaciones sin afectar otros módulos. RNF-13.12 Trazabilidad El sistema debe registrar eventos relevantes del usuario para análisis y seguimiento.

Modelo de Procesos (flujo detallado — BPMN textual) (Pasos claros, listos para pasar a Bizagi/Visio)

Inicio — Usuario abre formulario.
Ingreso de datos — Nombre, email, contraseña, confirmar, aceptar términos.
Validación en tiempo real — Formato email, fortaleza contraseña, chequeo unicidad (consulta DB). o Si falla formato/contraseña → mostrar mensaje y bloqueo. o Si email existe → mostrar opción “Recuperar contraseña”.
Captcha (si aplica) → completar.
Enviar registro → Generar registro provisional (estado: no verificado) y token.
Enviar email de verificación → email con token y link (caduca).
Usuario confirma → al hacer clic: validar token → activar cuenta (estado: activo).
Almacenamiento → Guardar: usuario, perfil, credencialesHash, fechaRegistro, logs.
Fin → Notificación final de bienvenida. Puntos de control: manejo errores (timeout, token expirado, duplicado), reenvío token, limitación de intentos.
